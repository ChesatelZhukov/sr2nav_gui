# SR2NAV GUI / SR2NAV Studio v2

Графический интерфейс для облегчения работы с пакетами **SR2Nav** и **Interval.exe**: подготовка входных файлов, управление запуском, просмотр результатов и расширенный анализ качества (скорости и GPS‑созвездие).

---

## 1. Запуск программы

### 1.1. Запуск из Python‑скрипта

1. Установите зависимости (Python 3.10+):
   - `tkinter` (обычно входит в стандартную поставку Python под Windows)
   - `matplotlib`
   - `numpy`
   - `pyperclip`
   - при наличии — `pywinstyles` (для тёмного заголовка окна, опционально)
2. Откройте папку проекта.
3. Запустите:

```bash
python main.py
```

При запуске из скрипта консоль **не скрывается** (это удобно для отладки).

### 1.2. Запуск из собранного `.exe`

Код адаптирован для упаковки (PyInstaller и т.п.): используются `sys.frozen` и `sys.executable`, рабочая директория определяется как папка рядом с `.exe`.

Рекомендуемая схема:

- собрать однопапочный вариант (`onedir`), чтобы рядом с `app.exe` лежали:
  - `Interval.exe`
  - `SR2Nav.exe`
- в собранном режиме консоль **прячется автоматически**, окно GUI остаётся.

> **Важно:** Приложение активно пишет файлы (`Mask.Ang`, `SR2Nav.cfg`, `Exclude.svs`, `interval.txt`, результаты расчёта) в рабочую директорию. Не размещайте `.exe` в каталоге без прав на запись (например, защищённый `Program Files`) без перенастройки путей.

## 2. Структура рабочего процесса

### 2.1. Основное окно

Основное окно (`MainWindow`) отвечает за:

- выбор входных файлов:
  - `SR2Nav.exe`
  - JPS‑файлы ровера и баз
  - POS‑файлы
  - файл гравики (`*.air`)
  - конфиг `SR2Nav.cfg` (опционально)
- выбор и редактирование **временного интервала**;
- выбор **угла отсечения** и управление исключением спутников;
- запуск:
  - только `Interval.exe`;
  - только `SR2Nav.exe`;
  - **полный цикл**: `Interval.exe` → разбор интервала → `SR2Nav.exe`;
- запуск окон анализа:
  - анализ скоростей;
  - анализ GPS созвездия.

Основные кнопки в верхней панели:

- **▶ SR2Nav** — запуск только `SR2Nav.exe` по выбранному конфигу и файлам.
- **⏱ Интервал** — запуск `Interval.exe`, разбор `interval.txt` и заполнение интервала.
- **▶▶ Полный цикл** — автоматический запуск `Interval.exe` → применение интервала → запуск `SR2Nav.exe`.
- **⏹ Стоп** — остановка текущего внешнего процесса (через асинхронный менеджер).

### 2.2. Рабочая директория и результаты

Рабочая директория определяется в `AppContext`:

- в режиме скрипта: корень проекта (`.../sr2nav_gui-...`);
- в режиме `.exe`: папка, где расположен исполняемый файл.

Используемые пути (`AppContext`):

- `working_dir` — рабочая директория (здесь ищутся/создаются файлы);
- `results_dir` — директория для результатов (по умолчанию `working_dir/results` или отдельная папка для каждого ровера);
- `tbl_dir` — подкаталог `tbl` для преобразованных файлов;
- `interval_exe` — путь к `Interval.exe` в рабочей директории;
- `sr2nav_cfg` — `SR2Nav.cfg` рядом с программой;
- `mask_ang` — файл `Mask.Ang` с углом отсечения;
- `exclude_svs` — файл `Exclude.svs` со списком исключённых спутников;
- `interval_txt` — `interval.txt` с результатом работы `Interval.exe`.

## 3. Файлы настроек и конфигурации

### 3.1. UI‑настройки (`user_prefs.ini`)

В каталоге `config` создаётся `user_prefs.ini` (через `UIPersistence`):

- последний использованный каталог (`LastUsed.directory`);
- последняя выбранная тема;
- геометрия окна (ширина/высота).

Файл создаётся/обновляется автоматически, вручную править не требуется.

### 3.2. Последние пути к данным (`user_paths.txt`)

Через `UserPathsStorage` сохраняются:

- последний путь к файлу ровера (`rover`);
- путь к `SR2Nav.exe`;
- пути к базам (`base1`, `base2`).  

Это позволяет при старте автоматически восстановить поля файлов в основном окне.

### 3.3. Угол отсечения (`Mask.Ang`)

Угол отсечения используется как параметр для SR2Nav и помощника по исключению спутников.

- Файл `Mask.Ang` находится в `working_dir`.
- При подготовке конфигов (`FileManager.create_config_files`) `Mask.Ang` создаётся/обновляется автоматически.
- Дополнительно реализовано **ручное обновление**:
  - в блоке «Угол отсечения» есть кнопка **«💾 Угол»**;
  - она устанавливает значение из поля в `FileManager` и перезаписывает `Mask.Ang` без запуска `Interval.exe`.
- При старте приложения `ApplicationController` пытается прочитать `Mask.Ang`:
  - если файл существует и содержит корректное число 0–90°, этот угол:
    - подставляется в UI;
    - запоминается в `FileManager`.

### 3.4. Исключённые спутники (`Exclude.svs`)

Через диалог «Исключить спутники» (меню **Инструменты → Исключение спутников**):

- хранится список вида `G01`, `G02`, …, `G32`;
- файл `Exclude.svs` создаётся при первом обращении (если отсутствует);
- формат — простой текст по одному PRN в строке.

### 3.5. Конфиг `SR2Nav.cfg` и `interval.txt`

При подготовке к запуску:

- `FileManager.create_config_files`:
  - создаёт/обновляет `Mask.Ang`;
  - генерирует `SR2Nav.cfg` с учётом:
    - интервала (авто или ручной);
    - путей к JPS‑файлам (ровер, базы);
    - файла гравики.
- Результат `Interval.exe` читается из `interval.txt`:
  - `FileManager.parse_interval_result` находит строку `[Common] ... -> [Common]`;
  - извлекает начало/конец;
  - обновляет `TimeInterval` и конфиг;
  - передаёт интервал в UI.

## 4. Управление интервалом времени

### 4.1. Автоматический интервал (через Interval.exe)

1. Укажите путь к JPS‑файлу ровера (и баз, при необходимости).
2. Нажмите **«⏱ Интервал»** или выполните **полный цикл**.
3. Поток:
   - копирование файлов в рабочую директорию при необходимости;
   - запуск `Interval.exe` (асинхронно, с таймаутом);
   - разбор `interval.txt` и установка интервала в UI.
4. Если до этого интервал был установлен **вручную**, авто‑результат может быть проигнорирован с соответствующим предупреждением.

### 4.2. Ручной интервал

В блоке «⏰ Начало / Конец»:

- введите время в формате GPS `YYYY:MM:DD:HH:MM:SS.f` (например, `2024:09:22:00:30:01.0`);
- нажмите кнопку **💾** справа от полей;
- при корректном формате:
  - `FileManager` переводит интервал в режим `manual`;
  - интервал сохраняется в `SR2Nav.cfg` (строка 4, `*start end`);
  - в блоке отображается режим **«✏️ ручной»**, а в выводе — соответствующее сообщение;
- при очистке обоих полей ручной режим сбрасывается.

## 5. Анализ скоростей (окно VEL)

Открывается через меню **Анализ → Анализ скоростей (VEL)**.

Возможности:

- автоматический поиск проектов: подкаталоги в рабочей директории, в которых есть `*.VEL` / `*.vel`;
- выбор проекта из списка или произвольной папки;
- построение графиков:
  - `RmsVel`;
  - высота `Hei`;
  - 4‑я разность высоты (как индикатор скачков);
- таблица с основной статистикой по каждому файлу;
- сводный текстовый отчёт;
- поиск и отображение `PDOP` из QC‑файла `Rover_Std.QC` (или первого доступного `*.QC`);
- выбор подмножества файлов для отображения;
- экспорт сводной статистики в CSV.

### 5.1. Удобство использования

- **Зум**:
  - прямоугольный зум мышью по левому клику/растяжению (через `InteractiveZoom`);
  - колесо мыши — масштабирование вокруг курсора;
  - двойной левый клик — сброс зума на текущей оси;
  - кнопка **«⟲ Сбросить зум»** — сброс зума на всех осях.
- **Панорамирование**:
  - **средняя кнопка мыши** (колёсико) — горизонтальный сдвиг всех осей по времени;
  - перетаскивание учитывает реальные пиксели экрана (без «дрожания» и рассинхронизации осей);
  - вертикальный сдвиг применяется только к активной оси.
- **Контекстное меню (правая кнопка)**:
  - копирование времени под курсором в формате `ЧЧ:ММ:СС.с`;
  - копирование пары `время + Y`;
  - отдельное окно с координатами не требуется, всё попадает сразу в буфер обмена.

Окно анализа **независимо** от основного — его можно оставлять открытым параллельно работе в главном окне.

## 6. Анализ GPS созвездия

Открывается через **Анализ → Анализ GPS созвездия**.

Возможности:

- анализ файлов `*.SVs` (и похожих по имени / регистру);
- построение **временной диаграммы видимости**:
  - по оси Y — спутники `G01`…`G32`;
  - по оси X — время наблюдения (относительное, `ЧЧ:ММ:СС.с`);
  - цвет/прозрачность полос отражает стабильность (частоту пропаданий);
- вычисление метрик для каждого спутника:
  - количество интервалов;
  - суммарное время видимости;
  - средняя/максимальная длительность;
  - интервалы/минуту;
  - категория (эталонный, хороший, умеренный, нестабильный, плохой, критический);
- сводные отчёты:
  - вкладка «Статистика и проблемы»
  - вкладка «Отчёт о качестве» (текстовый отчёт, пригодный для вставки в отчётность);
- экспорт результатов анализа в CSV.

### 6.1. Визуализация

- Окно графика спутников более компактное по вертикали и использует узкие полосы (height ≈ 0.5), чтобы удобнее помещаться на экране.
- В левом верхнем углу графика отображается текстовая сводка:
  - количество видимых спутников;
  - длительность наблюдения;
  - число спутников в каждой категории (Отл/Эт, Хор, Умер, Нест, Плох, Крит) **без вывода hex‑кодов цветов**.
- Легенда внизу объясняет цветовое кодирование категорий и маркеры проблемных спутников.

### 6.2. Взаимодействие

- **Зум и панорамирование** — те же принципы, что и в окне скоростей (`InteractiveZoom`):
  - прямоугольный зум;
  - колесо для масштабирования;
  - двойной клик / кнопка «Сбросить зум».
- **Контекстное меню (правая кнопка мыши)**:
  - копирование времени под курсором (GPS‑формат и человекочитаемый);
  - копирование времени и спутника с краткой статистикой;
  - открытие отдельного окна с подробной информацией по выбранному PRN.

Окно анализа GPS также **не блокирует** основное приложение.

## 7. Окно вывода и уровни сообщений

Все компоненты (контроллер, файловый менеджер, процесс‑раннер, анализаторы) отправляют сообщения через `AppMessage`:

- уровни: `DEBUG`, `INFO`, `SUCCESS`, `WARNING`, `ERROR`;
- форматируемая строка содержит время, префикс уровня и, опционально, источник (`[Controller]`, `[FileManager]`, и т.п.).

В окне вывода (`MainWindow`):

- сообщения уровней `INFO`, `SUCCESS`, `WARNING`, `ERROR` отображаются с цветовой подсветкой;
- **сообщения уровня `DEBUG` не выводятся**, но продолжат генерироваться внутри системы (например, для логирования в консоль/файл при необходимости);
- кнопки:
  - **«📋 Копировать»** — копировать весь текст вывода в буфер;
  - **«🧹 Очистить»** — очистить окно и вывести приветственный баннер.

## 8. Очистка рабочей директории

В меню **Инструменты → Очистить рабочую директорию**:

- удаляются все файлы в `working_dir`, кроме:
  - `*.exe`
  - `*.py`
  - (и, по умолчанию, директорий);
- ссылки на несуществующие временные файлы внутри `FileManager` также очищаются;
- перед удалением выводится предупреждение с подтверждением.

Это удобно для подготовки «чистой» папки перед новым запуском полного цикла.

## 9. Советы по использованию

- Держите `SR2Nav.exe` и `Interval.exe` **в одной папке** с GUI или явно укажите путь к `SR2Nav.exe` в поле SR2Nav.
- Для больших JPS‑файлов используйте окно сшивания (кнопка «Сшить» рядом с полями ровера и баз) — GUI корректно добавит заголовок `JP055` при необходимости.
- При проблемах с интервалом сначала убедитесь, что:
  - `interval.txt` создаётся;
  - строка `[Common]` присутствует;
  - формат времени соответствует ожидаемому.
- Если SR2Nav создаёт большое количество файлов, используйте функцию переноса результатов в `results_dir` — GUI автоматически переместит их в отдельную папку.

## 10. Обратная связь и доработки

Проект уже содержит множество улучшений по UX (тёмная тема, сглаженные стили, контекстные меню, подсветка уровней сообщений и т.д.). При необходимости можно:

- добавить новые виды анализа (например, по качеству фазовых измерений);
- расширить экспорт;
- подключить обычное логирование в файл на базе уже существующей системы `AppMessage`.

Для предложений и замечаний по логике работы или интерфейсу ориентируйтесь на текущий стиль кода в пакете `view` и `controller`.
